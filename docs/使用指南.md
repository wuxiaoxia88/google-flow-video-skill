# Google Flow Video Skill 使用指南

## 1. 工作边界

这套 Skill 由两部分组成：

1. `flowctl` 保存 Flow 作业、预算、请求哈希、浏览器票据、提交意图与恢复状态。
2. `scripts/production.py` 派生逐镜请求、准备统一配音、制作独立音轨、组装交付物并记录本地技术质检。

两部分的账本相互独立。MMX 配音不会计入 Flow Credits；Flow 作业记录也不能代替 TTS 授权和回执。实时浏览器操作由具备 Codex 浏览器连接的执行者完成，命令行只能生成和校验票据，不能自行控制 Chrome。

当前发布版为 Skill 0.3.8。它清理了不应发布的历史标识，并把受控补充重试改为当前任务、不可变请求和预算共同绑定的结构化授权契约。

## 2. 安装与运行目录

从公开仓库安装，不需要仓库访问授权：

```bash
git clone https://github.com/wuxiaoxia88/google-flow-video-skill.git
cd google-flow-video-skill
python3 google-flow-video/scripts/quick_validate.py
bash google-flow-video/scripts/install_skill.sh
```

仓库可公开下载不等于获得 Google Flow 或 MMX 的使用权限。实时操作仍需使用者自己的服务登录、可用额度，并满足当前任务的明确授权条件。

不要在 Git clone 或已安装 Skill 内运行 `pnpm install`、Flow 作业或生产命令。每次实际项目都从 Skill 复制一份 runtime 到新的用户工作目录：

```bash
SKILL_DIR="${CODEX_HOME:-$HOME/.codex}/skills/google-flow-video"
mkdir -p "$HOME/flowbridge-runs"
cd "$HOME/flowbridge-runs"
bash "$SKILL_DIR/scripts/bootstrap_runtime.sh" --workspace "$HOME/flowbridge-runs/flowbridge-run"
cd "$HOME/flowbridge-runs/flowbridge-run"
pnpm check
```

`bootstrap_runtime.sh` 要求目标目录尚不存在，复制锁定的 runtime 与测试，再执行 `pnpm install --frozen-lockfile` 和 `flowctl doctor`。需要 `Node.js 22`、`pnpm 11`、`ffmpeg`、`ffprobe` 和 Python 3。不要无理由改变 `package.json`、`pnpm-lock.yaml` 或 runtime 版本。

运行时数据库应放在项目自己的可写目录：

```bash
export FLOWBRIDGE_DB_PATH="$PWD/state/flowbridge.sqlite"
mkdir -p "$PWD/state"
pnpm --silent flowctl doctor
```

普通 `pnpm` wrapper 会在 stdout 打印脚本行；需要机器可读 JSON 时使用 `pnpm --silent flowctl ...`。

## 3. 浏览器与 Flow 前置条件

实时任务开始前，用户需要在受支持的浏览器中自行打开并登录准确的 Flow 项目页。执行 Agent 必须通过 Codex 支持的浏览器连接取得这个已经存在的标签页。

执行规则：

- 一次任务只有一个浏览器执行者。
- 每次接管前重新获取标签页清单，以 canonical Flow 项目 URL、可用时的 `providerTabId` 和可见项目身份匹配原标签页。
- 不新建标签页、窗口、浏览器配置或 Flow 会话；不复制 Cookie/Token/浏览器配置，不启用调试端口或安装扩展。
- 不关闭、重开、刷新或导航离开用户的 Flow 标签页。只有用户授权，或已经确认无未保存状态且需清除有记录的非编辑错误时，才可刷新。
- Agent 交接时只释放本地控制。不同执行者看到的浏览器 ID 可能不同，不能把旧 ID 当作 Chrome 标签页的永久身份。
- 旧句柄失效时只重新盘点一次并匹配同一项目页。找不到就以 `EXISTING_SESSION_REQUIRED` 停止，并保留页面现状。

sanitized observation 只能包含浏览器/标签页标识、canonical 项目 URL、观察时间、当前可见配置、余额、总费用、非 PII 账号指纹和可见素材引用。不得包含完整邮箱、页面里已有的提示词、Cookie、Token 或密码。

## 4. 锁定创意、镜头与音频策略

先保留两份不可变文本并记录 SHA-256：

- 创意母稿：用户确认的完整原始提示词。
- 音频覆盖：要求 Flow 不生成人声，只保留画面和背景音乐。

新中文本地化任务的音频覆盖应明确禁止 spoken language、dialogue、narration、lyrics 和 recognizable vocal sounds。它不能覆盖或改写创意母稿。

发布包中的有效音频政策入口是 [references/audio-policy.md](../google-flow-video/references/audio-policy.md)，安装版应以该 reference 和 `SKILL.md` 为准。

生产 manifest 的时间线必须连续。每个镜头都有自己的 `visual_scope`、起止时间、来源时长、当前可见 Flow 模型和 provider duration。`derive` 会把**完整原始提示词**保留到每个派生请求，再附加当前镜头的全局时间到片段时间映射和视觉/动作范围。不要把母稿压缩成只有镜头摘要。来源时长与交付时长不同的镜头，只有明确设置 `allow_retime: true` 才允许变速；变更时间线要披露并产生新哈希。

复制模板作为起点：

```bash
cp "$SKILL_DIR/templates/request.background_music_only.json" "$PWD/request.json"
cp "$SKILL_DIR/templates/delivery.manifest.template.json" "$PWD/production.json"
```

模板中的 `replace-with-*` 均需替换。不要把账号、Cookie、Token 或真实私有路径提交回 Git 仓库。

## 5. 本地准备与 50 Credits 规则

先验证生产 manifest 并派生逐镜请求：

```bash
python3 scripts/production.py validate --manifest "$PWD/production.json"
python3 scripts/production.py derive --manifest "$PWD/production.json" --out-dir "$PWD/derived"
```

每个 Flow 作业使用唯一且不可变的 `idempotency_key`；一个多镜头父任务共享同一 `budget_group`，每个镜头使用唯一预算 step。整个 Flow UI 父任务固定最多 **50 Credits**。页面上总费用未知或高于 50 时，不产生 provider effect。

可先建立预算并只保存请求：

```bash
LEDGER_ID="replace-with-ledger-id"
pnpm --silent flowctl budget create --id "$LEDGER_ID"
pnpm --silent flowctl budget status --id "$LEDGER_ID"
pnpm --silent flowctl generate --file /absolute/path/request.json --no-run
```

`--no-run` 只解析并保存本地作业，不会点击 Generate。保存源码、请求、哈希、runtime snapshot 和提交意图之后，才进入浏览器票据流程。

## 6. Agent 调用示例

准备与检查，不产生费用：

```text
使用 $google-flow-video 检查这个 Flow 视频请求。先锁定创意母稿、逐镜范围、50 Credits 总上限和 background_music_only 音频覆盖；只做离线验证和 --no-run，不点击 Generate。
```

明确授权一次实时生成：

```text
使用 $google-flow-video 执行已确认的作业。只复用我当前已经登录并打开的同一个 Flow 项目标签页，最终读回配置和总费用；总费用不明或超过 50 Credits 就停止。对这个 idempotency_key 只允许一次 Generate。
```

恢复已有作业：

```text
使用 $google-flow-video 恢复 job <job_id>。沿用原数据库、请求、idempotency_key 和 Flow 项目页，只观察、对账或下载；不要创建新作业，也不要再次点击 Generate。
```

制作统一中文配音：

```text
使用 $google-flow-video 按 production manifest 处理音频。Flow 输出保留画面和背景音乐，中文台词由 MMX 以同一模型、voice 和参数一次生成完整 take；保留 video_only、music_master、voice_master、final_redub，并在技术 QC 后等待人工试听。
```

这些提示不会绕过 Skill 内部的授权、费用和票据检查。旧对话、附件或普通的“继续”不能被推断为再次付费授权。

## 7. 实时浏览器票据

runtime 文档列出的当前命令面如下：

```bash
JOB_ID="replace-with-job-id"
TICKET_ID="replace-with-ticket-id"
pnpm --silent flowctl credits
pnpm --silent flowctl capabilities
pnpm --silent flowctl browser observe --file /absolute/path/sanitized-observation.json
pnpm --silent flowctl browser prepare --job "$JOB_ID" --observation /absolute/path/fresh-observation.json
pnpm --silent flowctl browser claim --ticket "$TICKET_ID" --observation /absolute/path/final-observation.json
pnpm --silent flowctl browser receipt --ticket "$TICKET_ID" --outcome clicked
pnpm --silent flowctl status "$JOB_ID"
pnpm --silent flowctl resume "$JOB_ID"
pnpm --silent flowctl cancel "$JOB_ID"
```

`browser observe/prepare/claim/receipt` 交换的是与 Codex executor 之间的本地记录；它们不会自行操作浏览器。执行者在 `claim` 后完成最后一次页面读回和已授权点击，再写入与真实操作匹配的 receipt。单独手工执行 `browser receipt ... --outcome clicked` 只是写下一项断言，不是浏览器点击证据。

`credits` 只接受页面上唯一可见的余额；`capabilities` 只报告当前可见的模型、模式、比例、时长、分辨率和输出数组合。缺失或歧义返回 `unknown`，不会使用静态能力表补齐。

## 8. 幂等、未知状态与恢复

提交意图一旦存在，Generate 自动关闭。以下情况默认都只能恢复原作业：

- 超时或进程崩溃；
- `SUBMISSION_UNCERTAIN`；
- `RESULT_AMBIGUOUS`；
- 页面结果与本地记录无法唯一对应；
- 下载失败但原输出仍存在。

保留相同数据库、请求文件、job ID、`idempotency_key`、项目页和账号/项目 fence：

```bash
JOB_ID="replace-with-job-id"
pnpm --silent flowctl status "$JOB_ID"
pnpm --silent flowctl resume "$JOB_ID"
pnpm --silent flowctl download "$JOB_ID"
```

不要通过创建新 key 或新作业绕过未知状态。只有 provider 明确失败、可证明未扣费、无新输出、前后资产集一致，且浏览器/标签页/账号/项目/请求 lineage 完全匹配时，才可能使用受控的失败重试：

```bash
RECONCILE_TICKET_ID="replace-with-claimed-reconcile-ticket-id"
FAILED_JOB_ID="replace-with-failed-job-id"
pnpm --silent flowctl browser fail --ticket "$RECONCILE_TICKET_ID" --evidence /absolute/path/failure-evidence.json
pnpm --silent flowctl browser retry-prepare --job "$FAILED_JOB_ID" --observation /absolute/path/fresh-observation.json
```

这条路径最多创建 attempt 2；attempt 3 被禁止。`SUBMISSION_UNCERTAIN`、`RESULT_AMBIGUOUS`、超时、崩溃或已有输出的作业不符合该重试条件。窄范围的 `user-resume-prepare` 只适用于当前用户明确授权再次付费，并且有完整 unresolved-job 证据与当前授权记录。授权记录必须绑定当前任务上下文、job/request hash、父预算、第二次尝试和授权证据哈希，且及时过期；旧契约版本的授权记录不兼容、不可复用，授权本身也不能替代 unresolved/output-free 与未扣费证明。不能从一般继续指令、旧对话或固定用户原话推断。

## 9. MMX 统一配音与音轨分离

中文台词优先以完整脚本一次生成，并在整个 take 使用相同 provider、model、voice 与 parameters。MMX 是此工作流已验证的外部配音后端。production CLI 根据 manifest 派生并绑定 MMX 参数，不接受任意生产 `argv`。

“已验证后端”不代表每台机器当前都可调用。真实提交前仍需检查该用户会话中的 MMX 安装、版本、模型/voice 可用性、认证和费用条件；`tts-submit` 不带 `--dry-run` 会产生外部 provider effect，必须已有当前授权。

```bash
python3 scripts/production.py tts-prepare --manifest "$PWD/production.json" --state-dir "$PWD/tts-state"
python3 scripts/production.py tts-submit --manifest "$PWD/production.json" --state-dir "$PWD/tts-state" --dry-run
python3 scripts/production.py tts-recover --state-dir "$PWD/tts-state"
```

真实 `tts-submit` 需要执行 Agent 根据当前任务里已经存在的授权生成匹配的 `current_run_tts_authorization`，绑定 `run_id` 和已准备请求的 SHA-256，并在 24 小时内有效。使用者不应手工伪造该记录。`--mock` 只能和 `--dry-run` 同用，并明确标为 `MOCK`。

成功必须产生新建、可 probe 的音频和绑定回执。已有输出、残留 process claim、非零退出或无法验证的输出都会进入 unknown；不会自动删除 claim 或盲目重跑。provider 未返回扣费信息时，`actual_cost` 保持 `null` 且状态为 `unknown`，不能写成零费用。

准备独立轨道并组装：

```bash
SOURCE_SHA256="replace-with-source-sha256"
python3 scripts/production.py prepare-video --manifest "$PWD/production.json" --out "$PWD/video-master.mp4"
python3 scripts/production.py voice-place --manifest "$PWD/production.json" --source "$PWD/full-take.wav" --source-sha256 "$SOURCE_SHA256" --out "$PWD/voice-master.wav" --gain-db -4
python3 scripts/production.py assemble --manifest "$PWD/production.json" --out-dir "$PWD/delivery"
```

最终保留：

- `video-only.mp4`：锁定画面，无音频；
- `background-only.mp4`：画面加背景音乐；
- `voice-master.wav`：从同一完整 take 按显式区间摆放的一致人声；
- `redub.mp4`：画面、背景音乐和统一中文配音。

`voice-place` 不改变台词速度；源台词片段长于目标窗口时直接拒绝。Demucs 只是可选的外部预处理工具，CLI 不下载模型，也不能自动证明分离后的音乐轨无人声。

CosyVoice 当前只是**未经验证的 adapter 候选项**。需要在本机另行安装并测试，不能打包模型权重，也不能声称已经支持或验证成功。

## 10. 本地测试与 QC

无费用验证：

```bash
python3 "$SKILL_DIR/scripts/quick_validate.py"
bash "$SKILL_DIR/scripts/execute_fixture.sh"
python3 -m unittest discover -s tests/production -p 'test_*.py'
pnpm check
```

fixture、mock 和 synthetic-media 结果必须按其真实标签报告，不能称为 live Flow 输出。新任务是否能实时生成，仍取决于新的用户授权、当前浏览器连接、页面状态和可见配置。

组装完成后执行：

```bash
python3 scripts/production.py qc --assembly "$PWD/delivery/ASSEMBLY.json" --out "$PWD/delivery/QC.json"
```

QC 会检查交付集合完整性、尺寸、帧率、时长、音频流拓扑，记录 `ffprobe`、完整 `ffmpeg -xerror` 解码和音量读回。还应检查首帧、尾帧和代表性画面，并单独取得 ASR 证据。

最终 `human_audio_status` 始终为 `REQUIRED`。人工需要试听普通话声调、音色一致性、残留人声、音乐/人声平衡，并检查口型和动作对齐。静态检查通过、ASR 文本正确或完整解码成功，都不等于成片已经通过验收。

## 11. 打包

从 `google-flow-video/` Skill 根目录运行：

```bash
bash scripts/package_skill.sh
```

脚本先运行 portable 校验，再按 allowlist 打包 `SKILL.md`、`PACKAGE.sha256`、`agents`、`references`、`templates`、`scripts`、`assets` 和 `tests`，输出版本化 ZIP、SHA-256 与文件列表。若相同版本的 archive 已存在，脚本会停止；应先做明确版本决策，而不是覆盖旧包。

发布到公开仓库前，另运行：

```bash
python3 google-flow-video/scripts/release_privacy_check.py --git-worktree .
```

它检查包内的合成 fixture 约束和全部可达 Git 提交的 noreply author/committer 元数据；内容检查通过不替代对公开 refs 与 GitHub 页面重新抓取复核。

仓库外层的 `README.md` 和 `docs/` 是 GitHub 使用文档，不进入 Skill ZIP。安装脚本从 `google-flow-video/` 复制，因此不受外层文档影响。

## 12. 常见问题

### 为什么出现 `EXISTING_SESSION_REQUIRED`？

当前执行者没有找到准确匹配、已经打开并登录的 Flow 项目标签页，或没有受支持的 Codex 浏览器连接。请在现有登录浏览器中打开目标项目页，再让执行者重新盘点一次。不要用新窗口、复制 profile 或重启浏览器绕过。

### 为什么费用明明可能很低，还是停止？

安全条件要求页面上总费用唯一、当前且可读。未知费用不是零费用；只要未知或超过整个父任务的 50 Credits 上限，就必须停在 provider effect 之前。

### `--no-run` 或 fixture 成功，是否代表 Flow 会生成成功？

不代表。它们验证本地请求解析、账本和安全控制，不验证当前账号、Flow 页面、模型供应、生成结果或下载。

### 提交后卡住，可以换一个 idempotency key 再试吗？

不可以。保留原数据库、job、请求和 key，先对账、恢复或下载。只有严格的 provider failure 且未扣费证据完整时，才可能进入受控 attempt 2。

### 能否让 Flow 直接说中文？

当前策略是 Flow 负责画面和背景音乐，最终中文对白由统一外部 TTS 提供。原对白仍作为表演和时间参考保存在派生提示词中，但 Flow 请求明确禁止生成可识别人声。

### 为什么分开保存音乐、人声和成片？

独立 stems 使来源、哈希、时长、混音和恢复都可检查，也方便只交付 `background-only` 或在人工听检后交付 `redub`。

### 支持 Windows、Linux 或任意浏览器吗？

仓库没有宣称跨平台或任意浏览器兼容。当前前置是 Node.js 22、pnpm 11、Python 3、FFmpeg，以及受支持的 Codex 浏览器连接。应在目标环境单独完成离线测试和实时连接验证后再下结论。

### CosyVoice 可以直接用吗？

目前不可以作为已验证能力来承诺。它只是候选 adapter，需要本机安装、接线和测试；仓库不包含模型权重。
